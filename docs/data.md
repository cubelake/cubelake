# Data: where it lives and in what shape

Everything is in a single region — `europe-central2`. BigLake requires this: buckets and datasets must
be in the same region. `<env>` is `d` (dev) or `p` (prod), `<rand>` is a random suffix generated by
Terraform (see `terraform output`).

## Storage map

| What | Where | Format | Written by | Read by |
| --- | --- | --- | --- | --- |
| Bronze, files | `gs://cbl-<env>-bronze-<rand>/<source>/<dataset>/snapshot_date=YYYY-MM-DD/<country>_<feed>.json` | NDJSON, 1 line = 1 API response | `sa-ingest` | BigLake (connection `lake`) |
| Bronze, tables | BigQuery `bronze_apple_rss.top_charts`, `bronze_apple_itunes.lookup` | BigLake external table over the files above | Terraform (definition only) | Dataform, analysts |
| Silver, tables | BigQuery `silver_apple_rss.top_apps`, `silver_apple_itunes.app_details` | Apache Iceberg managed table | Dataform (`sa-dataform`) | `sa-ingest` (iTunes), analysts, later gold |
| Silver, files | `gs://cbl-<env>-silver-<rand>/iceberg/<dataset>/<table>/` | Parquet + Iceberg metadata | **BigQuery only** | BigQuery, any Iceberg engine (Spark etc.) |
| Quality checks | BigQuery `dataform_assertions.*` | views | Dataform | Dataform |
| Docker images | `europe-central2-docker.pkg.dev/<project>/cubelake/cubelake-ingest:<tag>` | OCI | you / CD | Cloud Run |
| Terraform state | `gs://<your state bucket>/cubelake/` | tfstate | Terraform | Terraform |
| Dataform GitHub token | Secret Manager `dataform-github-token` | secret | you | Dataform agent |

> **Never edit files in the silver bucket by hand**: BigQuery manages them, and a manual edit will break
> the table. Change data only through Dataform or SQL.

## Bronze

### Path layout

```text
gs://cbl-d-bronze-7f3c/
  apple_rss/top_charts/snapshot_date=2026-10-11/
    us_top_free.json
    us_top_paid.json
    no_top_free.json
    … (175 countries × 2 feeds = up to 350 files per day)
  apple_itunes/lookup/snapshot_date=2026-10-11/
    us_top_free.json
    … (one file per feed that was in RSS that day)
```

Rules:
- `snapshot_date=YYYY-MM-DD` is a hive partition. BigQuery exposes it as a `snapshot_date DATE` column.
  **This field is not, and must not be, inside the files.**
- File name: `<country>_<feed>.json`, country in lowercase (`us`), feed is `top_free` or `top_paid`.
- Re-running a day overwrites that day's files. Previous versions are kept for 30 days because the
  bucket has versioning enabled.
- Bronze is kept forever. After 90 days objects move to the Nearline class (cheaper to store, more expensive to read).

### Record format

Each file contains **one JSON line** (NDJSON). Metadata fields come first, then the API response as-is:

| Field | Type | Meaning |
| --- | --- | --- |
| `_source` | string | `apple-rss` or `apple-itunes` |
| `_ingested_at` | string (ISO-8601 UTC) | when it was written |
| `_feed_type` | string | `top_free` / `top_paid` |
| `country` | string | lowercase country code |
| … | | API response fields |

Apple RSS: the file holds the `feed` object from the response. Sample response: `docs/apple_rss_sample_feed.json`.

```json
{"_source": "apple-rss", "_ingested_at": "2026-10-11T06:17:42+00:00", "_feed_type": "top_free",
 "country": "us", "title": "Top Free Apps", "id": "…", "updated": "Sat, 11 Oct 2026 06:00:00 +0000",
 "results": [{"id": "6448311069", "name": "…", "artistName": "…", "releaseDate": "2023-05-18",
              "kind": "apps", "artworkUrl100": "…", "url": "…", "genres": [ … ]}, …]}
```

iTunes lookup: the file holds the whole response of `https://itunes.apple.com/lookup?id=…&country=…`, i.e.
`resultCount` and `results[]` with the full app record.

This format is **stable**: already collected data and the silver models depend on it. New fields may be added;
existing ones must not be renamed or removed.

### Bronze tables in BigQuery

| Table | Source files | Schema |
| --- | --- | --- |
| `bronze_apple_rss.top_charts` | `apple_rss/top_charts/*` | `infra/terraform/schemas/bronze_apple_rss_top_charts.json` |
| `bronze_apple_itunes.lookup` | `apple_itunes/lookup/*` | `infra/terraform/schemas/bronze_apple_itunes_lookup.json` |

- The schema is explicit, no autodetection. Extra JSON fields are ignored (`ignore_unknown_values`).
- **A query without a `snapshot_date` filter will not run** (`require_partition_filter`). This keeps BigQuery
  from accidentally scanning the whole history.
- The BigLake metadata cache refreshes automatically, with an allowed staleness of up to 4 hours.

```sql
SELECT country, _feed_type, ARRAY_LENGTH(results) AS apps
FROM bronze_apple_rss.top_charts
WHERE snapshot_date = '2026-10-11';
```

## Silver

These are Iceberg managed tables: BigQuery holds the metadata, the data lives in our silver bucket as
Parquet. Tables are partitioned by `snapshot_date` and clustered by `country, feed_type`.
Loading is incremental: MERGE by key, so re-running a day is safe.

### `silver_apple_rss.top_apps`

One row per chart position: **day × country × feed × rank**. Key:
`(snapshot_date, country, feed_type, app_rank)`.

| Column | Type | Description |
| --- | --- | --- |
| `snapshot_date` | DATE | collection day (bronze partition) |
| `app_rank` | INT64 | chart position, 1–100 |
| `country` | STRING | ISO 3166-1 alpha-2, UPPER case |
| `feed_type` | STRING | `free` / `paid` |
| `snapshot_updated` | TIMESTAMP | chart time according to Apple |
| `app_id` | INT64 | App Store id (trackId) |
| `app_name`, `developer_name` | STRING | |
| `track_view_url`, `artwork_url` | STRING | |
| `release_date` | TIMESTAMP | |
| `_loaded_at` | TIMESTAMP | when Dataform wrote the row |

Checks:
- not null: `snapshot_date`, `app_rank`, `country`, `feed_type`;
- key is unique;
- `feed_type ∈ {free, paid}`;
- `app_rank` between 1 and 100.

### `silver_apple_itunes.app_details`

App record: **day × country × feed × app_id**. Key: `(snapshot_date, country, feed_type, app_id)`.

| Column | Type | Description |
| --- | --- | --- |
| `snapshot_date`, `country`, `feed_type`, `app_id` | | key (same as `top_apps`) |
| `app_name`, `bundle_id`, `developer_id`, `developer_name`, `seller_name` | | |
| `primary_genre_id`, `primary_genre_name`, `genres` | | `genres` is an array of strings |
| `price` | NUMERIC(2 decimals) | in `currency` |
| `currency` | STRING | UPPER case |
| `version`, `minimum_os_version`, `file_size_bytes`, `content_advisory_rating` | | `file_size_bytes` is INT64 (iTunes sends a string) |
| `release_date`, `current_version_release_date` | TIMESTAMP | |
| `average_user_rating`, `user_rating_count` | NUMERIC, INT64 | all time |
| `average_rating_current_version`, `rating_count_current_version` | NUMERIC, INT64 | for the current version |
| `description`, `release_notes` | STRING | |
| `artwork_url`, `track_view_url`, `language_codes`, `advisories`, `screenshot_urls`, `ipad_screenshot_urls` | | arrays are ARRAY<STRING> |
| `ingested_at` | TIMESTAMP | when the response landed in bronze |
| `_loaded_at` | TIMESTAMP | when Dataform wrote the row |

Checks:
- not null: `snapshot_date`, `country`, `feed_type`, `app_id`;
- key is unique;
- `feed_type ∈ {free, paid}`;
- `price` is null or ≥ 0.

```sql
-- top 10 free apps in the US with ratings
SELECT t.app_rank, t.app_name, d.average_user_rating, d.user_rating_count
FROM silver_apple_rss.top_apps t
JOIN silver_apple_itunes.app_details d USING (snapshot_date, country, feed_type, app_id)
WHERE t.snapshot_date = '2026-10-11' AND t.country = 'US' AND t.feed_type = 'free'
ORDER BY t.app_rank LIMIT 10;
```

## Naming

| What | Pattern | Example |
| --- | --- | --- |
| Projects | `prj-<d\|p>-cubelake-<rand>` | `prj-p-cubelake-a1b2` |
| Buckets | `cbl-<d\|p>-<bronze\|silver>-<rand>` | `cbl-p-bronze-7f3c` |
| Datasets | `<layer>_<source>` | `silver_apple_rss` |
| Bronze paths | `<source>/<dataset>/snapshot_date=D/<country>_<feed>.json` | `apple_rss/top_charts/snapshot_date=2026-10-11/us_top_free.json` |
| Silver files | `iceberg/<dataset>/<table>/` | `iceberg/silver_apple_rss/top_apps/` |
| Dataform files | `definitions/sources/<source>/<source>_<table>.sqlx` | `apple_rss_top_apps.sqlx` |
| Service accounts | `sa-<role>` | `sa-ingest`, `sa-dataform`, `sa-workflows` |

## Old data (Azure)

Bronze collected before the move to GCP lives in Azure ADLS Gen2 under
`bronze/appstore_rss/snapshot_date=D/<country>_<feed>.json` and `bronze/appstore_itunes/…`. The record format is
the same; only `_source` differs (`ingestion-apple-rss`). The migration is done by
[`scripts/migrate_azure_bronze.sh`](../scripts/migrate_azure_bronze.sh) (Storage Transfer Service, paths
`appstore_rss/` → `apple_rss/top_charts/`, `appstore_itunes/` → `apple_itunes/lookup/`), then silver
is rebuilt with a `{"rebuild_silver": true}` run. Step by step: [owner-tasks.md](owner-tasks.md).
